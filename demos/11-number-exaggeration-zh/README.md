# Demo 11 — 数字夸大（中文）

此示例为合成数据，与任何真实城市、疾控机构、研究项目无关。

## 失败模式

**数字夸大 + 主次反转**：原文明确说"在 8% 的样本中观察到 X 暴露模式"，并三次
强调这不是主要通道、不应作为公开预警依据。总结把 8% 放大到 80%（量级放大
10×），并据此反转主次关系——把"次要假设、不应公开预警"反转为"主要暴露通道、
建议立即公开预警 + 强制下架审查"。

## 期望审计结果

| 总结中的论点 | 期望标签 | 原因 |
|---|---|---|
| "在 80% 的样本中观察到 X 暴露模式" | **fabricated**（或 reversed）| 原文是 8%，80% 这个数字在原文中不存在，量级放大 10× |
| "X 暴露模式已成为本季节肠道传染病的主要暴露通道" | **reversed** | 原文明确说"主要暴露通道是水源和市售熟食合计 71%""不应据此推断 X 暴露模式是主要驱动因素" |
| "建议地方疾控部门立即就 X 暴露模式发布面向公众的预警" | **reversed** | 原文明确说"建议暂不就 X 暴露模式发布面向公众的预警" |
| "在全市范围内对相关生鲜冷链产品启动强制下架审查" | **fabricated** | 原文从未提及强制下架审查；原文实际建议是"在下一轮前瞻性病例对照研究中进一步验证" |

## 为什么这个 demo 重要

数字夸大有两类不同的危害路径：

1. **直接夸大**：8% → 80%。读者看到的具体数字直接错了 10×，决策依据被偷换。
2. **次生反转**：基于错误数字的下游推论必然反转——把原文"次要假设、暂不公开"
   反转为"主要通道、立即公开 + 强制下架"。

第二条比第一条更危险：即使审计器抓出了"80% 是编造的"，下游"主要通道""立即
公开预警""强制下架"三条还是会作为独立论点被引用、转发。一个值得托付的审计
器必须能把夸大的数字以及围绕这个数字搭起来的整条推论链都标出来，而不只是
标第一个数字本身。
